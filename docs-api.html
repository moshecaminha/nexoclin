API & Webhooks

Referência técnica da plataforma multi-tenant NexoClin: autenticação, escopo por clínica, endpoints REST, integração com a WhatsApp Business Platform (Meta) e webhooks.

1. Conceitos & multi-tenancy

A NexoClin é um SaaS multi-tenant: várias clínicas operam na mesma plataforma, cada uma com seu número oficial do WhatsApp, sua equipe e seus dados isolados. A unidade de isolamento é a clínica (clinic_id).

PapelEscopoPode
Super-admin (plataforma)GlobalVer todas as clínicas, mapa nacional, integrações, gestão de contas
GestorClínicaPerfil da clínica, equipe, agenda, onboarding (QR), relatórios
MédicoClínicaAtender, coletar dados, assinar documentos (ICP-Brasil), concluir
SecretariaClínicaAgenda, confirmações, retornos, fila
RecepçãoClínicaTriagem e roteamento da fila
Todo dado clínico (conversations, messages, documents etc.) carrega clinic_id e é protegido por Row-Level Security no banco: um usuário só enxerga linhas das clínicas em que é membro ativo. O super-admin tem acesso global via is_platform_admin().

2. Autenticação

Requisições autenticam com Bearer token (JWT de sessão do usuário) no header. O tenant é derivado da associação (membership) do usuário; para usuários multi-clínica, informe a clínica ativa em X-Clinic-Id.

GET /v1/conversations
Authorization: Bearer <jwt>
X-Clinic-Id: 3f9a...c21

Tokens de serviço (integrações servidor-a-servidor, ex.: o webhook receiver) usam a service_role e nunca são expostos ao navegador.

3. Endpoints REST base: https://api.nexoclin.com.br

Clínicas & equipe

GET/v1/clinics
Lista as clínicas do usuário (ou todas, se super-admin).
POST/v1/clinics
Cria uma clínica (onboarding). Body: nome, cnpj, endereço, cidade, uf, telefone_whatsapp.
PATCH/v1/clinics/:id
Atualiza perfil (foto, endereço, número oficial, plano).
GET/v1/clinics/:id/members
Equipe da clínica com papéis.
POST/v1/clinics/:id/members
Convida um membro (email + papel: gestor|medico|secretaria|recepcao).

Pacientes & onboarding

GET/v1/patients
Lista pacientes da clínica (filtros: nome, cpf, telefone).
POST/v1/patients
Cadastra paciente. CPF validado (dígitos verificadores); autocomplete de nome via provedor licenciado.
GET/v1/patients/lookup?cpf=
Consulta CPF em provedor licenciado (Serpro/Receita) com consentimento — retorna nome/nascimento.
POST/v1/invites
Gera um token de convite e o link/QR do WhatsApp. Body: patient_id?, label?. Retorna token + wa.me link.
GET/v1/invites/:token
Resolve um token (usado pelo webhook para identificar clínica + paciente quando a 1ª mensagem chega).

Atendimento

GET/v1/conversations
Fila de atendimentos (filtros: status, risco, atenção). Ordenada por gravidade.
GET/v1/conversations/:id
Detalhe do atendimento + dados coletados.
GET/v1/conversations/:id/messages
Histórico completo da conversa.
POST/v1/messages
Envia mensagem (texto/mídia). Dentro da janela de 24h. Body: conversation_id, type, body|media_id.
POST/v1/messages/template
Envia template (HSM) aprovado — necessário fora da janela de 24h (lembretes, confirmações).
POST/v1/media
Faz upload de mídia (áudio/imagem/PDF) e retorna media_id.

Documentos

POST/v1/documents
Cria rascunho (receita/atestado/resumo/encaminhamento) a partir do atendimento.
POST/v1/documents/:id/sign
Assina com ICP-Brasil (integração CFM/ITI) e anexa ao paciente. Retorna signature_ref.

Relatórios & notificações

GET/v1/reports/summary?period=90d
Indicadores agregados (atendimentos, exames, medicações, faltas, SLA, por bairro/estado).
GET/v1/notifications
Alertas do usuário/clínica (novo atendimento, ponto de atenção, SLA estourado, documento assinado).
PATCH/v1/notifications/:id/read
Marca como lida.

4. Webhook do WhatsApp (Meta) inbound

A NexoClin recebe os eventos da Meta Cloud API em um único endpoint. Cada número (Phone Number ID) é mapeado à sua clínica, garantindo o roteamento correto no multi-tenant.

4.1 Verificação (handshake)

GET /webhooks/whatsapp?hub.mode=subscribe
   &hub.verify_token=<VERIFY_TOKEN>&hub.challenge=123456
→ 200 text/plain: 123456   (se o verify_token conferir)

4.2 Recebimento de eventos

POST/webhooks/whatsapp
Recebe mensagens e status. Valida a assinatura X-Hub-Signature-256 (HMAC-SHA256 com o App Secret) antes de processar.

Eventos assinados: messages (recebidas), message_status (sent/delivered/read), message_template_status.

{
  "object": "whatsapp_business_account",
  "entry": [{
    "changes": [{
      "value": {
        "metadata": { "phone_number_id": "4471...1120" },
        "contacts": [{ "wa_id": "5521998124477", "profile": {"name":"Beatriz"} }],
        "messages": [{
          "from": "5521998124477", "id": "wamid...", "timestamp": "1718000000",
          "type": "text", "text": { "body": "Bom dia, meu filho está com febre" }
        }]
      }, "field": "messages"
    }]
  }]
}

4.3 Como cada evento vira dado

EventoAção na NexoClin
1ª mensagem (com código de convite)Resolve invite_token → identifica clínica + paciente → cria conversation (status nova)
message (texto)Insere em messages; alimenta a triagem/coleta (collected_data)
message (áudio/imagem)Baixa a mídia, transcreve/interpreta, marca "a validar" pelo paciente
ponto de atenção detectadoCria notification (tipo atencao) e eleva a prioridade (risco)
message_status = read/deliveredAtualiza o status da mensagem enviada
template_status = approvedLibera o template para uso em lembretes/confirmações
Segurança: requisições sem assinatura válida (X-Hub-Signature-256) são descartadas com 401. O App Secret e o access_token ficam em variáveis de ambiente do servidor/Edge Function — nunca no cliente.

5. Webhooks de saída outbound (opcional)

Para clínicas que querem integrar com seus próprios sistemas (ERP/prontuário), a NexoClin pode notificar eventos:

EventoQuando
atendimento.finalizadoMédico conclui o atendimento (prontuário + financeiro gerados)
documento.assinadoReceita/atestado assinado com ICP-Brasil
consulta.confirmadaPaciente confirma via WhatsApp
paciente.criadoNovo paciente cadastrado/onboarded

Entrega com assinatura HMAC própria da NexoClin no header X-Nexo-Signature e reentrega com backoff.

7. Uploads & storage

Arquivos (mídia do WhatsApp, PDFs, documentos assinados) ficam no bucket privado documentos do Supabase Storage, com convenção de caminho <clinic_id>/<conversation_id>/<arquivo>. O acesso é feito por URLs assinadas de curta duração geradas pelo servidor, garantindo isolamento por clínica. O upload direto do cliente passa por uma Edge Function que valida o tenant.

8. Segurança & LGPD

  • Isolamento por tenant: Row-Level Security em 100% das tabelas; o usuário só acessa dados das suas clínicas.
  • Segredos no servidor: access_token da Meta, App Secret e service_role nunca vão ao navegador.
  • Assinatura de webhook: validação X-Hub-Signature-256 em cada evento recebido.
  • Consentimento: registro do opt-in de LGPD por atendimento; base legal de tutela da saúde.
  • Documentos: validade jurídica via ICP-Brasil (CFM/ITI).
  • Auditoria: trilha por clínica em audit_log.
